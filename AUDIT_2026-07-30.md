## 1. Executive verdict

v2.6 closes the release-blocking problems found in the prior audit without rewriting the project's strong architecture. The three-day retreat now has one consistent browser/simulator lifecycle; spending cannot create a recoverable zero-money state; result-screen rollback is closed; rent prepayment extends correctly; milestones are monotonic; restarts reproduce their seed; and rival/nemesis arcs are ordered one-shot encounters.

The owner-directed content/art work is internally consistent. Sato is male in template, profile, portrait and events. The accidental standalone Oh is gone from the live cast, event pool, files and SHA manifest; Ahyeon Oh is canonical. All seven requested replacement portraits are clean full-bleed squares in both tiers, visually coherent at thumbnail scale, and byte-pinned. The new piano is a reproducible original synthesis with a sample-continuous loop boundary.

Fog's information design is materially better: it preserves location identity through positive focus icons while hiding arithmetic. Rotating choices now receive 31–47% of informed-model picks against a 25% test floor, while the 60-day difficulty gradient remains hard and non-binary.

## 3. Gameplay and lifecycle re-audit

### Three-day retreat — resolved

The browser and simulator now use the same lifecycle:

1. action resolves on day `N`;
2. two silent interior travel days resolve to `N+2`, including recovery and Sunday rent;
3. result modal reports the complete trip;
4. Continue advances to the next playable morning, `N+3`.

The player cannot take a second action on `N+2`, and the simulator no longer receives a different day/recovery sequence than production. UI and core regressions cover the return day and fatal travel rent.

### Bankruptcy and transactions — resolved

- Prepay/renovation rejects an exactly wallet-emptying transaction.
- Negative/zero prepayment week counts reject safely.
- Repeated payments target the next uncovered Sunday.
- Prepay, renovation and perk purchases save immediately.
- All regular turn paths still permit action/event recovery before the final turn game-over check, preserving the documented turn-order design.

### Persistence — resolved

A nonfatal resolved turn now writes game state, event RNG/scheduler and the pending result before displaying the modal. Reload restores that modal and exact totals. Continue clears `pendingResult`, advances once and writes the next morning. This closes full-choice rollback without pretending a result was never shown.

### Endings — resolved

`won` now means “day-60 endurance was ever earned.” A later death ends the run but does not rewrite history. `survivalRate` was added to simulator summaries for horizon survival so long-run tests no longer misuse the monotonic goal flag.

### Seed/restart — resolved

Event manager reset now reseeds from the reset game's city seed. Fresh boot and Begin Again produce the same first event schedule/RNG state for a shared seed.

## 4. Balance re-audit

### Current 60-day contract

300 deterministic seeds through the actual hub; day 60 resolves:

| Model | Death | Goal | Mean survival |
| --- | ---: | ---: | ---: |
| Does not pay attention | 100% | **0%** | 13d |
| Random | 73% | **27%** | 33d |
| Greedy preview reader | 73% | **27%** | 41d |
| Average proxy | 58% | **42%** | 42d |
| Sometimes attentive | 55% | **45%** | 44d |
| Concentrates | 39% | **61%** | 49d |
| Min-maxing | 34% | **66%** | 50d |

The desired shape holds:

- founding-pair blindness always dies;
- random/naive greed succeeds about one in four;
- average remains inside the 35–50% contract;
- attention creates a clear slope;
- no model is immortal.

### Rotating-location contract

The appeal pass improves Free Clinic, Soup Kitchen, Library, Open Mic and Letting Office while retaining costs. Across informed models, rotating cards receive:

| Model family | Rotating pick share |
| --- | ---: |
| Sometimes attentive / average | about 46–47% |
| Greedy | about 31% |
| Concentrates | about 31% |
| Min-maxing | about 35% |

All clear the new **25% minimum**. This measures “choose one of the four rotating offers,” not 25% per individual location, which would be mathematically impossible alongside two founding cards and four simultaneous rotating cards.

### Simulator fidelity — explicitly pending

The simulator is still a regression instrument, not a human prediction. Pending items are recorded in `notes/SIMULATOR_FIDELITY_PENDING.md`:

1. models score exact averages under fog/rain/snow while players see focus icons or bands;
2. decision and event draws share one simulator RNG stream;
3. simulation event seed uses `seed + 7`, unlike production's direct city seed;
4. long-horizon models buy perks but not renovations;
5. utility functions are authored proxies without human-playtest validation.

The long-trip lifecycle mismatch is fixed; these other items are deliberately not marked resolved. CI writes the pending warning beside every balance report.

## 6. Art, portraits and audio re-audit

### Requested portrait corrections

Visually inspected masters and 288px contact sheet:

- Ahyeon Oh — female florist, Paris market/garden context;
- RicardoEA — male electrical engineer/radio workbench;
- Renata — female, calm bathhouse context;
- Brendan — male teacher in LoC Mines context;

- Cat — actual male domestic cat in the meditation hall.

All seven are 1024×1024, full-bleed, and free of baked circular/oval frames, mats and white edges. Thumbnail and hi tiers are 288×288 and 896×896. The manifest pins all three files per live character; any pixel change now fails tests until deliberately re-approved/re-pinned.

### Portrait sizing root cause

The old generic portrait rule declared `width:56px`, `height:56px`, but `flex: 0 0 42px`. Flex layout squeezed the horizontal dimension while preserving height, causing small/oval People portraits. The v2.6 hierarchy is explicit and square:

- Léon HUD: 110px;
- character detail: 96px;
- People rows: 72px;
- location host/event portrait: 64px;
- compact host: 30px.

Every rule uses equal width, height and flex basis with `border-radius:50%` and `object-fit:cover`. Side characters remain subordinate to Léon without becoming thumbnails too small to read.

### Piano

`comfy_piano.wav` is synthesized from code, not sampled:

- 52 BPM;
- Am9 → Fmaj7 → Cmaj7/G → G6;
- soft additive felt-piano harmonics, sparse broken chords, pedal/body resonance;
- 18.46 seconds;
- mono, 16-bit PCM, 22.05 kHz;
- 795 KiB;
- exact zero sample jump at the loop boundary after smooth correction;
- reproducible seed and stdlib-only generator.

The old pad and generator are deleted. Browser music remains opt-in/lazy to respect autoplay and payload.

### Provenance caveat

Most content and art remains recorded as AI-generated. This is transparent in the templates and not a technical blocker for the free Pages build. Commercial storefront release still needs an owner-approved per-asset provenance/license strategy; SHA manifests prove bytes, not rights.

## 7. UI, accessibility, security and performance

### UI/accessibility improvements verified

- Fog shows only positive focus icon(s), no numbers/signs/reasons.
- Rain/snow remain qualitative bands.
- People uses native button semantics with `aria-pressed`; no false listbox promise.
- Navigation focuses the destination heading.
- Portrait lightbox contains Tab, supports Escape and restores prior focus.
- In-game Reduced Motion prevents particle creation/timers and hides the layer; OS preference still works.
- Persisted settings normalize booleans and clamp volume to `[0,1]` before audio assignment.
- Footer small-text contrast is raised above AA.
- Copy Link has explicit action and success/fallback toast.

A real NVDA/VoiceOver and hardware touch pass was not performed. jsdom verifies behavior/wiring, not actual browser focus traversal, layout, image decode or screen-reader speech.

### Security/privacy

- no backend, accounts, telemetry, ads, cookies or third-party runtime scripts;
- no runtime npm dependency;
- dependency audit: zero vulnerabilities;
- restrictive CSP added;
- unused `innerHTML` helper path removed;
- user-visible dynamic content remains text-based;
- local storage is schema-validated where it can affect audio/UI.

`window.__game` remains intentionally available for a local single-player debug experience. Anti-cheat has no product value here.

### Performance

The static/no-build architecture remains fast and durable. Portrait replacements reduce the hi tier by roughly 0.22 MB and the piano is smaller than the pad it replaces. Conservative eager-tier headroom remains tight (0.17 MB); future art should optimize before increasing the 4 MB budget.

## 10. Final assessment

The game is healthier after v2.6 in the places that matter most: a day means one day, a three-day action consumes three days, zero money cannot be escaped through a side transaction, saves preserve decisions, narrative conclusions follow introductions, cast identity matches the art, and rotating choices meaningfully compete with the founding pair.

The implementation stays proportionate. No framework, backend, account system or engine migration was introduced. The strongest existing advantages—static durability, deterministic rules, catalogue-wide tests, authored tone and a simple daily decision—remain intact.

**Final recommendation:** approve v2.6 for merge after existing remote CI, make `crazy-branch` the repository default, verify Pages, then apply the CI upgrade with a workflow-authorized GitHub connection. Continue treating simulator fidelity, human playtesting and repository/LFS cleanup as explicit next-cycle work rather than retroactively calling them solved.
